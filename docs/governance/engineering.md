# 通用工程约束

本文定义 AI 在本仓库执行工程任务时遵守的长期质量约束。仓库特有事实由
[`repository.md`](repository.md) 补充；当前用户任务仍然决定本次范围。

## 范围与完整实现

- 只实现当前任务要求的行为，不增加假设性字段、能力、抽象、目录或扩展点。
- 不进行与任务无关的重构、依赖升级、格式化或清理。
- 一个需求涉及多个层次时，完整更新受影响的代码、数据、协议、测试、生成产物和
  文档。
- 分批实现和验证是风险控制手段，最终结果不得遗留双轨实现、重复入口或无价值的
  临时结构。
- 不以缩小 diff 为理由保留已失去用途的内部兼容壳，也不以追求最终形态为理由扩大
  产品范围。

## 建模与完整性

- 数据结构、键、约束和操作来自当前真实查询、用例与不变量。
- 每个公共能力和持久化字段都应有当前调用者、读写者或明确所有者。
- 完整性约束放在能够权威表达它的最底层可靠边界，例如类型、schema、数据库约束
  或协议定义；上层提前报错不能代替权威约束。
- 数据、事务、锁、认证、重试和副作用顺序必须定义失败行为。
- 结构化数据通过结构化 API 或解析器处理，不依赖脆弱的字符串拼接。

## 职责与抽象

- 业务规则与传输入口、进程装配和具体基础设施保持分离。
- 消费者定义所需的最小能力接口；调用方负责依赖注入、装配和生命周期。
- 协议入口负责方法、状态、序列化等协议语义；adapter 负责依赖类型、转换、错误
  映射和隔离。
- 新层必须承担验证、转换、编排或隔离等真实职责，不能只转发调用。
- 新抽象必须消除真实复杂度、建立清晰所有权或减少有意义的重复。
- 不引入全局可变单例、隐藏注册表或难以隔离测试的静态状态。

## 复用与依赖

- 修改前检查标准库、当前仓库能力和锁定依赖是否已满足契约。
- 优先采用仓库已有且符合当前权威契约的模式、helper 和错误边界。
- 新依赖必须解决标准库或既有依赖无法合理满足的当前需求。
- 依赖行为以实际锁定版本的契约和源码为准，不依赖其他版本的印象。
- 不为本地命名偏好修改上游接口，也不复制依赖内部实现绕过缺失能力。

## 权威来源与生成内容

- 每个 schema、协议、查询和生成表示应有唯一且明确的权威来源。
- 生成内容必须通过正式流程更新，不能手工伪造或保持多份人工同步副本。
- 内部接口变化同时更新声明、实现、调用方、测试、示例、文档和生成绑定。
- 计划、设计草案和历史说明不能作为当前运行行为的证明。

## 兼容性

内部代码默认不增加只用于改名、转发、re-export 或保留旧入口的兼容层。
兼容层只在存在真实边界价值时保留，例如：

- 已发布公共 API 的明确弃用周期；
- 线上协议的跨版本互操作；
- 数据迁移或滚动部署中的短期共存；
- adapter 承担转换、权限、审计、指标或依赖隔离。

保留兼容层时，必须明确兼容对象、当前使用者、覆盖测试以及删除条件。

## 错误与外部边界

- 复用仓库既有的错误身份、构造方式、错误链和响应机制。
- 不同失败条件保持可区分；依赖错误在 adapter 边界转换为领域含义。
- 保留有用根因，只在最终处理边界记录一次错误。
- 用户可见错误不得泄露内部实现、凭据或敏感上下文。
- 验证、认证、授权、缺失、冲突、限流和依赖故障应得到明确映射。
- 损坏输入、业务失败或副作用失败不得报告为成功。
- Panic 或进程终止只用于不可恢复的编程错误或静态装配错误。
- 网络、文件、子进程和临时资源都必须有明确的超时、取消或清理边界。

## 测试

- 新增或改变的行为在最近的责任层获得行为覆盖。
- 缺陷修复增加能够复现原始失败模式的回归场景。
- 跨层测试覆盖协议、装配和关键协作，不重复所有下层案例。
- 当约束、事务、锁、查询或外部协议的真实语义是测试目标时，使用真实系统；替代
  实现只用于它能够忠实表达的行为。
- 覆盖正常路径、非法输入、资源上限、错误映射、失败恢复以及适用的重试、取消、
  超时、并发和幂等性。
- 测试资源具有有界清理；异步测试使用条件等待和明确超时，不用固定 sleep 猜测完成。
- fixture 和 helper 不复制生产决策逻辑。

## 完成标准

- 先运行最接近改动的检查，修复失败后再按风险扩大验证矩阵。
- 编译通过或单个 focused test 通过不等于任务完成。
- 完成前检查完整 diff、格式、静态分析、测试、生成同步、契约和文档。
- 完整验证不得静默跳过所需外部依赖；无法运行的检查必须明确报告。
- 只报告当前 checkout 上实际执行的命令及结果。
- 最终 diff 必须聚焦且完整，不含无关修改、临时调试内容、凭据或本地产物。
