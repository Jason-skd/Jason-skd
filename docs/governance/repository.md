# 本仓库工程边界

本文只记录当前仓库特有的事实来源、架构边界和验证入口。通用工程规则见
[`engineering.md`](engineering.md)。

## 当前状态与迁移基线

- 本仓库正在把 GitHub 主页生成流程重写为 Zig 程序。
- [`docs/zig_rewrite.md`](../zig_rewrite.md) 是已确认的 MVP 范围、目标模块边界和验收
  计划，但计划中的能力在对应实现与测试落地前不得描述为当前行为。
- `main` 分支是当前投入使用的 Python 实现，也是 Zig 重写的行为迁移基线。替换一项
  能力前，必须检查 `main` 中对应的配置、实现、测试、fixture、工作流和生成结果，
  明确哪些行为需要保持、哪些行为由重写计划有意删除。Python 的模块结构和实现方式
  不构成 Zig 架构或代码风格范例。
- `../github-stats` 是同领域的 Zig 参考实现，可用于比较 GitHub API、Git 子进程、统计
  聚合、资源管理和构建方式。它当前面向 Zig 0.16，且产品范围与本仓库不同，因此其
  API 用法和设计不能直接移植；采用相关做法前，必须同时通过本仓库契约、`main`
  行为和当前 Zig 0.17 官方源码验证。

## Zig 0.17 证据要求

- 本项目使用的 Zig 0.17 nightly 源码位于 `../zig`，编译器入口为
  `../zig/build/stage3/bin/zig`。开始工作前必须核对该编译器版本满足
  `build.zig.zon`，并确认 `../zig` checkout 与实际编译器对应。
- 修改 `.zig` 源码、`build.zig` 或 `build.zig.zon` 前，必须针对本次涉及的 API、
  所有权、错误处理、内存管理、I/O、测试方式和代码组织，搜索并阅读 `../zig` 中相关
  的官方实现、测试与调用点。允许为获得可靠结论读取更多相邻上下文。
- 训练语料、旧版本经验、第三方示例和搜索结果只能作为定位线索。API 正确性以当前
  `../zig` 源码和实际编译结果为准；代码风格与实践优先跟随官方相邻实现及测试。
- 因官方源码形成重要实现判断时，在任务说明或代码评审证据中记录关键文件路径与
  符号，避免结论无法追溯。

### 源码先行门禁

任何修改 `.zig`、`build.zig` 或 `build.zig.zon` 的任务，在第一次文件编辑前必须完成
并明确报告以下证据：

1. 实际使用的 Zig 可执行文件、`zig version` 和对应源码 revision；
2. 本次会触及的 Zig API、资源所有权、错误边界和构建行为；
3. 对应源码定义，以及至少一个官方调用点、测试或项目模板；
4. 锁定第三方依赖的实际 manifest、公开模块名和相关 API 源码。

只运行编译或测试不能替代源码调查。若已经开始编辑才发现门禁未完成，必须暂停继续
扩展改动，补读源码，并按新证据重新审查已有 diff 后才能继续。最终交付必须列出形成
重要判断的源码文件与符号；无法取得对应源码时，不得声称实现已按当前 Zig 最佳实践
验证。

## Zig 实践缓存

- 已稳定并重复验证的结论记录在 [`docs/zig_practices.md`](../zig_practices.md)，同时
  保持 README 文档索引同步；不为单次局部观察扩张该文档。
- 每条实践记录适用范围、推荐做法、必要的关键代码片段、验证方式、Zig 版本或 commit，
  以及结论来源的准确文件路径、符号或测试段落。
- 后续任务先查阅该文档以减少重复读取；工具链 revision 变化、缓存结论与源码冲突或
  新 API 不在记录范围内时，必须重新读取 `../zig`。该文档是检索缓存，不替代官方
  源码这一权威来源。

### 任务结束时的缓存判定

每个获得写入授权的 Zig 实现、修复或重构任务，在最终交付前必须主动检查本次源码
调查是否形成新的可复用实践，不等待用户提醒。结论同时满足以下条件时，必须在本次
任务中更新 `docs/zig_practices.md`：

1. 直接来自当前锁定 Zig 或依赖源码，而不是仅来自编译结果、经验或猜测；
2. 已通过相关构建、测试或最小复现场景验证；
3. 会影响后续任务的 API 选择、资源所有权、错误处理、I/O、模块边界、构建图、测试
   组织或依赖管理；
4. 具有超出当前局部实现的一般复用价值，并且现有缓存尚未完整覆盖。

缓存更新必须写明适用范围、推荐做法、工具链版本或 revision、源码文件与符号、验证
方式以及已知失效条件。一次性排障过程、未确认假设、仅对当前 diff 有意义的细节和
可由源码名称直接读出的常识不得写入缓存。

只读调查或评审任务不得因此获得写入权限；这类任务只在交付中报告值得缓存的候选
结论。工具链 revision 变化时，应先复核受影响条目，只更新已重新验证的内容，不批量
刷新版本文字。新增、移动或删除实践文档时同步 README 索引；只更新既有条目时不要求
制造无关索引改动。
