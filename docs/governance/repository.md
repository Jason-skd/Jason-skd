# 本仓库工程边界

本文只记录当前仓库特有的事实来源、架构边界和验证入口。通用工程规则见
[`engineering.md`](engineering.md)。

## 当前状态与迁移基线

- 本仓库正在把 GitHub 主页生成流程重写为 Zig 程序。
- [`docs/zig_rewrite.md`](../zig_rewrite.md) 是已确认的 MVP 范围、目标模块边界和验收
  计划，但计划中的能力在对应实现与测试落地前不得描述为当前行为。
- `main` 分支是当前投入使用的 Python 实现，也是 Zig 重写的行为迁移基线。替换一项
  能力前，必须检查 `main` 中对应的配置、实现、测试、fixture、工作流和生成结果，
  明确哪些行为需要保持、哪些行为由重写计划有意删除。Python 的模块结构和实现方式
  不构成 Zig 架构或代码风格范例。
- `../github-stats` 是同领域的 Zig 参考实现，可用于比较 GitHub API、Git 子进程、统计
  聚合、资源管理和构建方式。它当前面向 Zig 0.16，且产品范围与本仓库不同，因此其
  API 用法和设计不能直接移植；采用相关做法前，必须同时通过本仓库契约、`main`
  行为和当前 Zig 0.17 官方源码验证。

## Zig 0.17 证据要求

- 本项目使用的 Zig 0.17 nightly 源码位于 `../zig`，编译器入口为
  `../zig/build/stage3/bin/zig`。开始工作前必须核对该编译器版本满足
  `build.zig.zon`，并确认 `../zig` checkout 与实际编译器对应。
- 修改 `.zig` 源码、`build.zig` 或 `build.zig.zon` 前，必须针对本次涉及的 API、
  所有权、错误处理、内存管理、I/O、测试方式和代码组织，搜索并阅读 `../zig` 中相关
  的官方实现、测试与调用点。允许为获得可靠结论读取更多相邻上下文。
- 训练语料、旧版本经验、第三方示例和搜索结果只能作为定位线索。API 正确性以当前
  `../zig` 源码和实际编译结果为准；代码风格与实践优先跟随官方相邻实现及测试。
- 因官方源码形成重要实现判断时，在任务说明或代码评审证据中记录关键文件路径与
  符号，避免结论无法追溯。

## Zig 实践缓存

- 当重写的模块边界和工具链用法趋于稳定，并且同类实践已经重复验证后，在 `docs/`
  下建立 `zig_practices.md`，同时更新 README 文档索引。在此之前不为零散观察提前
  创建该文档。
- 每条实践记录适用范围、推荐做法、必要的关键代码片段、验证方式、Zig 版本或 commit，
  以及结论来源的准确文件路径、符号或测试段落。
- 后续任务先查阅该文档以减少重复读取；工具链 revision 变化、缓存结论与源码冲突或
  新 API 不在记录范围内时，必须重新读取 `../zig`。该文档是检索缓存，不替代官方
  源码这一权威来源。
